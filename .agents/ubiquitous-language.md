| Term | Canonical type | Aliases to avoid | Notes |
|------|----------------|------------------|-------|
| Vault | `vaultRoot` / `VaultState` (`src/stores/app-store.ts`, `src-tauri/src/vault.rs`) | workspace, project folder | User-selected root directory. Backend filesystem operations accept canonical paths inside it and reject paths or symlinks that escape it. |
| Vault entry | `VaultEntry` (`src-tauri/src/vault.rs`) | file node, tree node | A visible Markdown file or directory in the vault tree; hidden and symlinked entries are omitted. |
| Vault-change event | `vault-changed` | filesystem refresh | Watcher event carrying touched paths. It drives refreshes rather than callers mutating the cached tree. |
| Vault entry creation | `create_note`, `create_directory` (`src-tauri/src/vault.rs`) | touch | Creates an empty in-root note or directory without clobbering an existing entry; the parent must exist. Two commands because their behavior genuinely differs (`.md` appending vs. `create_dir`) — unlike deletion, which is one. Three callers share `resolveDraftParent`: the `a`/`A` chords, the sidebar header buttons, and the *sidebar context menu*. |
| Vault entry duplication | `duplicate_entry` / `duplicateVaultEntry` (`src-tauri/src/vault.rs`, `src/lib/vault/duplicate-entry.ts`) | copy | Creates a sibling copy of an in-root note or directory, selecting the first available ` copy` suffix. The frontend moves the sidebar cursor to the returned path on success; the watcher owns tree refresh and the duplicate is not opened. |
| Vault entry deletion | `delete_entry` / `delete_entry_in`, `VaultError::NotFound` (`src-tauri/src/vault.rs`) | remove, unlink, `fs::remove_*` | Moves an entry to the **OS trash** via the `trash` crate — never `fs::remove_file`/`remove_dir_all` (ADR 0012), so Finder is the recovery path and there is deliberately no in-app undo. One command for files *and* directories, because `trash::delete` treats them identically. `guarded_path` supplies containment, canonicalization and leaf-symlink rejection; deletion adds the two guards it cannot: an explicit vault-root rejection (`starts_with` is reflexive, so the root would otherwise pass) and an existence check (`NotFound`). |
| Vault entry rename | `rename_entry` / `rename_entry_in` (`src-tauri/src/vault.rs`), `renamePath` (`src/stores/sidebar-store.ts`) | move, relocate | Renames an entry **within its existing parent** — it is deliberately not a move, so no `move_entry(from, to)` exists and drag-to-move stays unbuilt. A note's *stem* is what gets edited; `with_md_extension` reappends `.md`, so a rename can never turn a note into a non-note. Every editor buffer at or under the old path has its `filePath` and title **rewritten in place** — dirty ones keep their unsaved edits — rather than being closed as deletion closes them: a rename destroys nothing, so it must cost nothing. For a note it also triggers a *wikilink rewrite*; for a directory it never does. |
| Vault entry duplication | `duplicate_entry` / `duplicate_entry_in` (`src-tauri/src/vault.rs`) | copy, clone, `fs::copy` | Copies a note *or* a directory beside itself under a derived name — `X copy`, then `X copy 2`, `X copy 3` on collision, always applied to the **stem** so `note.md` becomes `note copy.md`. Directories are copied by a hand-rolled recursive walk that skips symlinks, mirroring `build_tree`'s filter — no `fs_extra` dependency. Unlike *vault entry creation* it never opens the result in a buffer: duplicating is a filing action, so it only moves the sidebar cursor onto the copy. A derived name is never a link target that existed before, so it rewrites nothing. |
| Wikilink rewrite | `rewrite_wikilinks` (`src-tauri/src/vault.rs`) | link index, backlinks, reindex | The vault-wide scan that repoints `[[old stem]]` at a renamed note's new stem. A **scan, never an index** (ADR 0016) — v0-spec reserves the index for the post-v0 graph. Its grammar is narrower than the *wikilink* decoration's: the target is everything before the first `\|`, an anchor (`#…`, `^…`) is preserved verbatim, and comparison is case-insensitive because the macOS filesystem is. It walks the same file set the sidebar shows — `build_tree`'s filter, minus the root `AGENTS.md`/`CLAUDE.md`, whose template text contains a literal `[[Wikilinks]]`. **An ambiguous stem cancels it**: two notes sharing the old basename means no rewrite at all plus a toast, because the link model cannot express which note a link meant. Only a note rename triggers it; a directory rename cannot, since a target is a basename and carries no path. |
| Rename confirmation | `RenameEntryDialog` | rename dialog, rename prompt | The gate in front of a *wikilink rewrite*, shaped like the *delete confirmation* but shown **only when the scan finds at least one link** — a note nobody links to, and every directory, renames with no overlay at all. It exists to consent to writing in *other people's notes*, not to protect the renamed file, which is why `N = 0` means no dialog. Counts first, then the affected notes listed as in the dirty-buffer block. Its confirming action is a `secondary` button, never `primary` or `danger`: a rename is neither an AI action nor a destructive one, and both filled variants stay reserved (invariants 21, 27). |
| Sidebar context menu | `useContextMenuStore` / `SidebarContextMenu` (`src/stores/context-menu-store.ts`, `src/components/vault/SidebarContextMenu.tsx`) | popover, dropdown, native menu | App-drawn overlay, not `tauri::menu::Menu::popup` (ADR 0013). Mounted in `Layout`, **never** inside `Sidebar` — that body is `overflow-y-auto` inside an `overflow-hidden` row, so a menu rendered in place would clip. Carries an explicit `target: string \| null` (`null` = vault root) rather than reading `cursorPath`, though right-clicking a row sets the cursor too so one row is visibly the acted-on one. Expanded sidebar only — never the *sidebar rail*. Mouse-only: it has no arrow-key navigation, because every item already has a chord and `FileTreeItem` has no `tabIndex` by design. Its item list is fixed at **New note · New folder — Rename · Duplicate — Summarize note · Find related notes — Move to Trash**, in four hairline-divided groups, every row carrying a glyph and a *live chord hint*. What varies is only *presence*: an item that cannot apply to the target is **hidden, never disabled** — background (root) shows the create pair alone, a directory adds Rename/Duplicate/Move to Trash, and only a note gets the AI group. The two AI rows are permanently disabled placeholders; `Copy link` from the source mockup was deliberately not built. |
| Delete confirmation | `requestDeleteConfirmation` / `useDeletePrompt` (`src/lib/vault/confirm-delete.ts`), `DeleteEntryDialog` | delete dialog, "are you sure" | The promise-shaped gate every deletion passes through, mirroring `useVaultSwitchPrompt`'s shape so `deleteVaultEntry` reads linearly. Always shown, even though trash makes the file recoverable — because the *unsaved edits* it discards are not, and this is the only surface that can disclose them. Its presentation is fixed: a *modal shell* at 460px carrying a `--danger-soft` icon tile, the target as a *vault display path* in its own mono field, counts-first body copy with a concordant verb (`1 note moves` / `2 notes move`), the buffers line only when buffers will actually close, the dirty-buffer block last above the footer, and a footer pairing `recoverable from Trash` with the app's only `danger` button. |
| Delete summary | the frontend-computed `{ counts, openBuffers, dirtyBuffers }` behind a *delete confirmation* | — | What the dialog body adapts to: entry counts for the deleted subtree, every buffer that will close, and the affected dirty buffers. Computed frontend-side by walking the cached `useSidebarStore.tree` and intersecting `editor.buffers` by path prefix — the vault tree is already in memory, so this needs no new IPC and `delete_entry` stays a bare `Result<()>`. |
| Vault agent context | `AGENT_CONTEXT_FILES` (`src-tauri/src/vault.rs`) | system prompt, vault README | The `AGENTS.md` and `CLAUDE.md` instructions scaffolded in an adopted vault root for engines running there. |
| Wikilink scan and rewrite | `WikilinkScan` / `WikilinkRewrite`, `scan_wikilink_targets` / `rewrite_wikilinks` (`src-tauri/src/{wikilink,vault}.rs`) | backlink index, global replace | The backend-only workflow that parses narrow `[[target]]` syntax across visible vault Markdown notes, reports target-stem ambiguity, and rewrites only unambiguous target spans while preserving aliases and anchors. Root agent-context templates are excluded; nested `AGENTS.md` remains a note. |
| Sidebar store | `useSidebarStore` (`src/stores/sidebar-store.ts`) | tree store, vault store | Owns cached tree, expanded directories, keyboard cursor, and pending entry draft or rename. |
| Entry draft | `EntryDraft` / `EntryDraftKind` (`src/stores/sidebar-store.ts`) | pending file, rename state | A not-yet-created note or directory being named. It is distinct from a dirty editor buffer. |
| Entry rename | `renamePath` / `beginRename` / `cancelRename` (`src/stores/sidebar-store.ts`) | entry draft, pending file | The existing vault entry being renamed inline. It is mutually exclusive with an entry draft because a rename has a concrete target path. |
| Vault file candidate | `VaultFileCandidate` (`src/lib/vault/file-search.ts`) | search result | A searchable file with absolute/synthetic path, relative path, name, and a `source: 'vault' \| 'config'` discriminant. `collectVaultFiles` produces the vault ones; `collectConfigCandidates` unions in the two config files under a synthetic `config/`-prefixed path, bypassing the vault-root prefix filter entirely (ADR 0004). |
| File finder | `useFileFinderStore` / `FileFinder` | command palette, Spotlight | Transient overlay that ranks vault file *and* config file candidates and opens the selected one, routed by `source`. It is not a focus region. |
| Open vault file | `openVaultFile` (`src/lib/vault/open-file.ts`) | load file | Activates an already-buffered path without rereading or replacing dirty content; otherwise reads it into a buffer, then calls `focusEditor` — moving both the focus region and real DOM focus into the editor. |
| Sidebar row | `FlatVaultRow` / `flattenVisibleTree` (`src/lib/vault/flatten-tree.ts`) | `SidebarRow`, `flattenSidebarRows` | The sidebar has exactly **one** row source: the visible vault tree. The second source that once concatenated a pinned Config section onto it is gone (ADR 0010), and with it the synthetic cursor key, the per-row routing switch, and the vault-only guard on `a`/`A`. |
| Sidebar rail | the collapsed `Sidebar`, `--rail-sidebar-collapsed` (40px) | "hidden sidebar", "activity bar" | What `sidebarExpanded === false` renders instead of nothing: the brand mark, the expand toggle, `⌕`/`✎`/`⊞`, and one glyph per *root entry*. It is a **launcher, not a preview** — a root file opens and leaves the rail collapsed, while a root directory (and either create action) expands first, because neither has anywhere to render at 40px. Reflects the active buffer only; no dirty dot. It has **no context menu** — a destructive action on a 40px glyph identified by hover tooltip alone is a misclick waiting to happen, and it has no draft row to render a create into either. |
| Root entry | a direct child of `vaultRoot` — `tree` itself, un-flattened | "top-level file" | The rail's entry list. Directories *and* notes, in tree order, each disambiguated by a native `title` — there is no tooltip primitive in the repo. |

Clicking one still does nothing, despite the `cursor: pointer`. |

| Open config file | `openConfigFile` (`src/lib/config/open-config-file.ts`) | load config | Opens a config file as an `EditorBuffer` with `source: 'config'`, mirroring `openVaultFile`'s dedup-by-existing-buffer behavior (invariant 6) so an already-open config buffer is activated, never re-read over unsaved edits. | Config buffer vs. disk change | `warnDirtyConfigBuffers` (`src/hooks/use-config-watcher.ts`) | config reload | Extends invariant 6: a `config-changed` event never touches an open config buffer's `content` (only `useSettingsStore`/`useKeymapStore` reload their own separate state) — it only toasts when the touched file has a *dirty* config buffer open, so a later `:w` is a conscious overwrite rather than a surprise. |
| App command | `AppCommandId` / `AppCommandDescriptor` / `APP_COMMANDS` (`src/lib/app-command.ts`) | keybinding, action | Fully-qualified dotted id (e.g. `global.find-file`, `sidebar.cursor-down`) for an action dispatched outside a focused text input. `editor.*` and `modal.*` ids are declared but not yet wired to a live dispatch layer. | Chord | `Chord` / `ChordKey` / `parseChord` (`src/lib/keymap/chord.ts`) | keybinding string | A parsed CodeMirror-notation key sequence (e.g. `"ctrl-w f"`). The single parser shared by the window dispatcher (`src/lib/keymap/dispatcher.ts`) and the CodeMirror layer (`regionExit`); `mod-` resolves to Cmd on macOS or Ctrl elsewhere at match time, named keys normalize to their exact `KeyboardEvent.key` form (`Escape`, not `escape`), and a single-character base key compares case-insensitively so a `shift-` modifier composes correctly with a shifted letter's uppercase `KeyboardEvent.key`. |
| Keymap layer | `KeymapLayer` (`src/lib/keymap/defaults.ts`) | region, scope | The subset of `AppCommandLayer` the keymap resolver and dispatcher operate over: `'global' \| 'sidebar' \| 'chat.history' \| 'modal'`. Excludes `'editor'` — CodeMirror wins that layer by DOM event-propagation order before the dispatcher runs, so it is out of the resolver's scope. `'modal'` was resolved-but-unconsumed from #97 until the *sidebar context menu* became its first consumer via `useModalKeymap`; it now sits **first** in `LAYER_PRECEDENCE` and is the only layer that swallows (invariant 25). |
| Layer swallow | `DispatcherLayer.swallows` (`src/lib/keymap/dispatcher.ts`) | modal lockout, focus trap | Whether an *active* layer absorbs a keydown its trie does not match, instead of letting the dispatcher try the next layer. Only the `modal` layer sets it. Not a focus trap — it governs the shared window-level dispatcher, not DOM focus, and does not stop CodeMirror (which wins by event-propagation order before the dispatcher runs at all). |
| Default keymap | `DEFAULT_KEYMAP` (`src/lib/keymap/defaults.ts`) | hardcoded chords | The code-side default chord(s) for every command in a `KeymapLayer`, written exactly as they'd appear in `keymaps.toml`. | Resolved keymap | `ResolvedKeymap` / `resolveKeymap` (`src/lib/keymap/resolve.ts`) | parsed config | The merge of `keymaps.toml`'s parsed value over `DEFAULT_KEYMAP`: per command, an override **replaces** the default wholesale (never merges), `[]` unbinds it. Chord conflicts within a layer resolve first-wins by command order; a chord that is both a leaf and the prefix of another reverts its whole layer to defaults. Every degradation raises a `KeymapDiagnostic` without failing the rest of the file. |
| Keymap store | `useKeymapStore` (`src/stores/keymap-store.ts`) | config store | Holds the current `ResolvedKeymap`, seeded synchronously from `resolveKeymap(null)` (the all-defaults keymap) so the dispatcher is correct before `load()` resolves. `load()` reads `keymaps.toml` via `useConfigStore` and toasts every diagnostic. |
| Keymap dispatcher | `createDispatcher` / `KeymapDispatcher` / `DispatcherLayer` (`src/lib/keymap/dispatcher.ts`) | keydown listener | The single shared window-level `keydown` handler that replaced three independent, racing listeners (`useGlobalKeymap`, `useSidebarKeymap`, `useChatHistoryKeymap` each used to own one). Builds one chord trie per registered layer; walks layers in a fixed precedence order (`modal`, then region layers, then `global`) and dispatches the first active layer's match — leaf or valid prefix — with no fallthrough to a lower layer. Note "no fallthrough" applies only to a *match*: an active layer whose trie does **not** match is skipped and the walk continues, which is why region chords stayed live under every dialog's scrim until the `modal` layer gained *layer swallow* (ADR 0014). `useDispatcherLayer` is the React hook each keymap hook uses to register its layer. |
| Live settings reload | `useConfigWatcher` / `useSettingsStore.applyReloadedSettings` (`src/hooks/use-config-watcher.ts`, `src/stores/settings-store.ts`) | settings hot-reload | Debounced `config-changed` handler for `settings.toml`. `applyReloadedSettings` returns `'echo'` (a reload matching this store's own last write, via `lastWrittenSnapshot` — no state change), `'syntax-error'` (last-good `settings` kept, only `diagnostics` updates), or `'applied'` (a genuine external edit). |
| Vault switch | `switchVault` / `useVaultSwitchPrompt` / `SwitchVaultDialog` (`src/lib/vault/switch-vault.ts`, `src/components/layout/SwitchVaultDialog.tsx`) | vault reopen | Live-applies a changed `vaultPath`: closes every open buffer through the existing `closeBuffer` lifecycle, gated by one consolidated Save all / Discard all / Cancel prompt when any buffer is dirty. ## Invariants and relationships

1. Focus regions remain reachable only while their corresponding region is *usable*: the chat while it is open, the sidebar while it is **expanded** — not merely visible (see invariant 24).
2. Global mode and editor Vim mode remain separate state machines.
3. Keyboard layers dispatch shared app commands rather than duplicating command behavior.
4. Vault filesystem operations remain contained within the canonical vault root and reject symlink escapes.
5. Vault creation refreshes through the watcher; callers do not mutate the cached tree directly.
6. Opening an already-buffered note activates it without replacing dirty in-memory content.
7. Save requests are immutable snapshots processed in FIFO order, and completion applies only to the captured revision.
8. Dirty buffer close cannot discard changes without an explicit user decision.
9. System yank updates the Vim register independently from asynchronous clipboard success.
10. The selected model determines the agent source; the engine is never persisted separately.
11. Agent backends translate native output into `AgentEvent`; UI and chat state do not consume raw engine output.
12. `useChatStore`, chat persistence, and chat-history view state remain distinct concepts.
13. Chat-file parsing and serialization own the format while persistence owns storage.
14. Resume prompts are used only when backend session memory cannot be relied upon.
15. A `vaultPath` change is never applied while dirty buffers are unresolved without an explicit consolidated decision; Cancel leaves it un-applied.
16. A config file's `EditorBufferSource` and its buffer's `filePath` decide save routing, editor language, and wikilink suppression together; no call site re-derives them from the path independently.
17. A `config-changed` disk event never mutates an open config buffer's content, dirty or not — it only ever toasts a warning when the buffer is dirty (extends invariant 6).
18. Keymap resolution replaces a command's chords wholesale; chord lists are never merged entry-by-entry, and an empty list unbinds.
19. Keymap layers resolve in a single dispatcher, `editor > active region > global`, first match wins with no fallthrough.
20. Real DOM focus follows the focus region: while `activeRegion === 'viewer'` with an active buffer, that buffer's CodeMirror view holds DOM focus, and it releases it as soon as the region moves elsewhere. Both halves are load-bearing — the window dispatcher bails on any `contenteditable` target, so region focus without DOM focus leaves an opened note untypable, and DOM focus without region focus leaves the other regions' keys landing in the buffer.
21. The AI accent marks AI agency and nothing else. No success state, status indicator, brand mark, or decorative fill may use it; a UI element rendering it is asserting that the agent acted there — or, at disabled opacity, that an AI action is offered here and not yet available. The sole exception is an icon that never renders inside the window — the **app icon** and the **favicon** — which is therefore not app chrome and cannot compete with the *chat toggle* (ADR 0032). `AcidantheraMarkGlyph`, the same mark drawn for in-app use, is monochrome.
22. acidanthera token names are the only token vocabulary. Factory token names and aliases no longer exist.
23. There is no bottom status bar. Editor state renders inside the editor (the editor status cluster) and global controls live in the titlebar (ADR 0009). New state goes on the surface that owns it; a shared bar is not an option.
24. The sidebar is always visible and never unmounts; collapsing it yields the *sidebar rail*. A collapsed rail is deliberately **not** a reachable focus region — it has no visible cursor for `j`/`k` to move — so `collapseSidebar` moves `activeRegion` off `'sidebar'` and the focus cycle skips it (ADR 0011).
25. While a `modal` layer is active it absorbs every keydown — matched or not — so no lower layer dispatches under an overlay (ADR 0014). Both the *sidebar context menu* and the *delete confirmation* register it, so `j`/`k`/`a`/`A`/`d d` are inert under either. Registration is the *modal shell*'s job, not each dialog's, which is what closes the leak for `CloseBufferDialog` and `SwitchVaultDialog`. `SettingsDialog` and `FileFinder` stay outside the shell and outside the layer: each already blocks keys its own way — a `stopPropagation` on the panel, and a focused input that trips `isEditableTarget`.
26. A vault deletion moves the entry to the OS trash and never calls `fs::remove_*`. It closes every editor buffer at or under the deleted path, and discards those buffers' unsaved edits only behind an explicit *delete confirmation* — which is why the confirmation is unconditional even though the file itself is recoverable from Finder.
27. The *destructive color* marks the destructive path, and nothing else — the menu row that initiates it and the button that commits it (ADR 0015, narrowed). A failed operation stays monochrome. Together with invariant 21 this leaves the app exactly two colored fills — ember for "the AI acted here", red for "this click destroys" — and a UI element rendering either is asserting one of those two things.
28. Renaming a **note** rewrites every `[[wikilink]]` whose target is its old stem, unless that stem is ambiguous — two notes sharing it means nothing is rewritten and the user is told (ADR 0016). Renaming a **directory** rewrites nothing, because a wikilink target is a basename and carries no path. The rename lands first and is never rolled back; the rewrite that follows is best-effort and reports what it could not do.
29. A rename never closes a buffer. Every buffer at or under the old path has its `filePath` rewritten in place, dirty ones included — the mirror of invariant 26, where deletion closes them, because deletion removes the file and a rename does not.
30. Every drawn icon comes from Lucide through the `Icon` primitive (ADR 0017), which is the only place `strokeWidth={1.2}`/`absoluteStrokeWidth` is set. Hand-drawn SVG survives in exactly one component, `AcidantheraMarkGlyph`; the *Unicode glyph vocabulary* stays characters inside text and is not an exception to this, because it is typography.

### Scaffold and orchestration

31. **A command triad moves as a unit.** Renaming, adding, or deleting a slash command touches all three of its files in the same change; a partial triad fails the acceptance gate.
32. **A review finding is a hard violation only if it breaches the glossary or an ADR.** Everything the Fowler smell baseline surfaces is a judgement call, no matter how confident the reviewer is. A documented repo standard overrides the baseline where the two disagree.
33. **The Standards axis and the Spec axis are never merged or reranked against each other.** A change can pass one and fail the other; combining them lets the passing axis mask the failing one.
34. **Axis isolation is blindness between findings, never exclusivity over sources.** The Standards and Spec sub-agents may be handed the same pre-read source material; what they must never see is each other's findings or a merged ranking of them.
35. **The runner is the sole writer of the epic integration branch, on both execution paths** (ADR 0020). A review gate changes *when* a child is merged, never *who* merges it — the agent only reads epic branch state and opens the final PR.
36. **Review state is derived from git, never stored** (ADR 0021). A child awaits review if its remote branch exists and the epic branch carries no `Merge child #N` for it; rework rounds are counted from commit markers. There is no durable state file to disagree with the repository.
37. **Every child passes an agentic review before it can be integrated, on both execution paths.** What differs is who resolves a finding: on the supervised path a hard violation pre-selects rejection and the human decides; on the auto path it blocks integration and triggers rework directly. Never whether the review runs.
38. **Both execution paths run one pipeline** (ADR 0023). Run → review → optional rework → integrate. No path has a shortcut that merges without review — that is what removing the inline merge bought.
39. **A rejection triggers rework; a merge conflict does not.** A conflict is an integration problem and goes to guided recovery in the child's direction; rework is for "this is not what I asked for."
40. **The shape of a session is chosen at the call site, never in `.agents/parallel.config`** (ADR 0022). That file is gitignored and per-machine, so it may hold operational knobs (concurrency, timeouts, caps) but nothing that decides whether a human is required.
41. **A review gate never emits a merged verdict.** It presents both axes side by side and one objective *gate line* counting hard violations and judgement calls. Counting is not reranking; the moment a gate collapses the two axes into a single approve/reject, the passing axis starts masking the failing one (extends invariant 33).
42. **Work is not done until an agentic review has seen it.** Under an epic that means before integration; interactively it means after the acceptance criteria pass and before `/execute-issue` reports completion. What varies across paths is who resolves a finding, never whether the review runs — with exactly one declared exception: `skip review` on the interactive path, which a human chooses at the call site and which must be stated in the final report. No path may skip the review by omission, by configuration, or silently (generalizes invariant 37).
43. **A review report is an artifact, never review state.** Persisting one does not contradict invariant 36: nothing reads a report back to decide what stage a change is at. The moment something did, the file could disagree with the repository — which is the failure ADR 0021 exists to prevent.
44. **Every source a reviewer needs arrives by path, already materialized.** The corpus pack, the issue body, the plan, the design spec and the diff are all written to disk *before* the review prompt is built, on both paths. A reviewer sent to *find* a source has an unbounded search space, and the observed failure is not that it costs more but that it reads less and reports shallowly — or never returns. A wall-clock cap (`REVIEW_TIMEOUT` per reviewer attempt, `AGENT_TIMEOUT` per implementing agent) exists to catch that, never to make it tolerable.
45. **An issue label is informational; nothing in the pipeline reads one back** (ADR 0031). Neither execution path, the runner, nor the review gate branches on a label. The moment one did, GitHub would become a source of execution state that can disagree with the repository — which is exactly what invariant 36 exists to prevent.
46. **Labels are written at creation and corrected only by `/update-issue`.** `/create-issue` and `/spec-breakdown` set them; `/update-issue` may fix them, because correcting an inaccurate generation is what that command is for. `/ship-note`, `/comment-issue`, `/execute-issue` and `/handoff` still never send labels.
47. **Applying a label is best-effort and never blocks issue creation.** A decorative metadatum must not be able to stop the issue from existing — and GitHub already behaves this way, silently dropping labels from a token without push access rather than failing the request.
48. **A child never inherits its epic's labels.** Every issue is labelled from its own content; propagating the epic's labels down would give every child the same set and destroy the filter's value. The `> Epic: #<n>` body header is what groups them.

## Flagged ambiguities

- **Global versus editor Vim mode.** `GlobalMode` is the app-shell normal/command state; `EditorVimMode` is CodeMirror state for an editor buffer. Do not merge them. Only `EditorVimMode` is ever *rendered* — as bare text in the editor status cluster, never as a chip. They were once two identical `<Badge tone="muted">` 36px apart, which is precisely how users came to believe they were one thing (ADR 0009); the survivor has since dropped its box as well, so nothing in the app renders a mode badge at all.
- **Adapter versus backend.** An adapter is a concrete per-engine translator; `AgentBackend` is the interface it implements.
- **Collapsed sidebar versus folded directory.** Two senses of "expanded" that are not the same state. `sidebarExpanded === false` collapses the whole region to the *sidebar rail*; a folded directory is one path missing from `useSidebarStore.expanded`. The rail can show a directory whose contents are folded, and expanding the sidebar does not unfold anything by itself.
- **Entry draft versus entry rename.** Both render an inline input on a sidebar row and share one input component, but they are different states in different slots: an `EntryDraft` is an entry that does not exist yet, `renamePath` points at one that does. Only the second can break links or invalidate an open buffer's path. A third `EntryDraftKind` was rejected for exactly that reason.
- **Entry draft versus dirty editor buffer.** An `EntryDraft` has not reached disk. A dirty buffer is an existing note with unsaved content.
- **Buffer versus tab.** `EditorBuffer` is session state; an editor tab is its UI representation.
- **Engine versus model.** The model is user-selected; its derived `AgentSource` identifies the CLI. Persist the model, never a separate engine.
- **Three chat stores.** `useChatStore` owns the in-memory transcript, `chats.rs`/`chatsService` own durable storage, and `useChatHistoryStore` owns history-browser view state.
