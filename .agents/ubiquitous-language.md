# Ubiquitous Language

> Single source of truth for current **product** terminology — the vocabulary of acidanthera
> itself. Read the row for a term before changing its canonical type, state, process, or data
> contract.
>
> **Last updated:** 2026-09-11
> **Canonical code:** `src/` (TypeScript), `src-tauri/src/` (Rust)

## The five files

| File | Holds | Always in context? |
|------|-------|--------------------|
| `.agents/ubiquitous-language.md` | product vocabulary (this file) | no — read on demand |
| `.agents/ubiquitous-language-index.md` | term → area pointers, generated | **yes** |
| `.agents/ubiquitous-language-invariants.md` | invariants **1–38** | **yes** |
| `.agents/ubiquitous-language-scaffold.md` | harness vocabulary + invariants **39–56** | no (ADR 0041) |
| `.agents/ubiquitous-language-changelog.md` | historical record | no — and not in the corpus pack |

The index and the invariants are `@`-imported by `CLAUDE.md`; this body is not (ADR 0041). An
invariant constrains all code, so it is always loaded; a term's definition matters only to work
that touches that term, so it is fetched when the index points at it.

## How to maintain this document

1. **Describe current behavior**, not release history or superseded implementations.
2. **A term enters when its code lands**, never when it is designed (ADR 0042). A term settled
   during a `/grill` waits in the spec's `## Glossary Changes` until the implementation merges.
   There is no marker for a term that is settled but unbuilt — that convention is abolished.
3. **The one-claim rule.** A row states what the term **is**, its canonical type, and the one
   distinction that would otherwise be got wrong. Rationale belongs in the ADR the row cites,
   not restated beside the citation.
4. **600 bytes per Notes cell**, and per invariant. `.agents/scripts/verify-scaffold.sh` §11
   fails the build above it (ADR 0043). If a row cannot fit without losing a distinction, move
   that distinction into its ADR — if it has no ADR, that is the signal it should.
5. **The retirement test.** Remove the row if doing so would not change what anyone writes.
   An *aliases to avoid* entry is **not** evidence of value: the table template asks for one, so
   nearly every row has one.
6. **The whole file is capped**: `verify-scaffold.sh` warns at 80,000 B and fails at 100,000 B.
   Retirement is how the cap is answered, not routine pruning.
7. **Record the change** in `.agents/ubiquitous-language-changelog.md` as a **one-line** row —
   date, what changed, and a pointer to the spec / ADR / issue — and update `Last updated` above.
8. After adding or renaming a term, run `sh .agents/scripts/build-glossary-index.sh` and commit
   the regenerated index; §11 diffs it against a fresh build.

## Vault and note navigation

|------|----------------|------------------|-------|
| Vault | `vaultRoot` / `VaultState` (`src/stores/app-store.ts`, `src-tauri/src/vault.rs`) | workspace, project folder | User-selected root directory. The root held in `VaultState` is **canonical by construction** — both adopt paths (`open_vault` via `prepare_vault_root`, `pick_vault` via its own canonicalization) resolve it before storing, so no downstream caller re-canonicalizes it and the same folder yields one string whichever way it was opened. Backend filesystem operations accept canonical paths inside it and reject paths or symlinks that escape it. |
| Vault entry | `VaultEntry` (`src-tauri/src/vault.rs`) | file node, tree node | A visible Markdown file or directory in the vault tree; hidden and symlinked entries are omitted. Carries `modified` — an mtime read from one `fs::metadata` call inside the walk `build_tree` already performs — which the sidebar renders as a *note row*'s `edited 3m`. Outgoing link counts are deliberately **not** here: they would cost a full read of every note in the vault per computation, which is exactly the price ADR 0016 refused. |
| Vault-change event | `vault-changed` | filesystem refresh | Watcher event carrying touched paths. It drives refreshes rather than callers mutating the cached tree. |

The folder defaults to `daily`, created on first use, and the one configurable part. The **filename is hardcoded** ISO 8601: the command parses the name back to find today's note before creating one, ISO making the sidebar's order chronological. The file is created **empty**. Unlike an *entry draft* it never asks for a name: the date is the name. **It swallows `AlreadyExists` rather than reading the tree first**: the cached tree may lag, while Rust is already the authority on collision. |
| Vault entry duplication | `duplicate_entry` / `duplicateVaultEntry` (`src-tauri/src/vault.rs`, `src/lib/vault/duplicate-entry.ts`) | copy | Creates a sibling copy of an in-root note or directory, selecting the first available ` copy` suffix. The frontend moves the sidebar cursor to the returned path on success; the watcher owns tree refresh and the duplicate is not opened. |
| Vault entry deletion | `delete_entry` / `delete_entry_in`, `VaultError::NotFound` (`src-tauri/src/vault.rs`) | remove, unlink, `fs::remove_*` | Moves an entry to the **OS trash** via the `trash` crate — never `fs::remove_file`/`remove_dir_all` (ADR 0012), so Finder is the recovery path and there is deliberately no in-app undo. One command for files *and* directories, because `trash::delete` treats them identically. `guarded_path` supplies containment, canonicalization and leaf-symlink rejection; deletion adds the two guards it cannot: an explicit vault-root rejection (`starts_with` is reflexive, so the root would otherwise pass) and an existence check (`NotFound`). |
| Vault entry rename | `rename_entry` / `rename_entry_in` (`src-tauri/src/vault.rs`), `renamePath` (`src/stores/sidebar-store.ts`) | move, relocate | Renames an entry **within its existing parent** — it is deliberately not a move, so no `move_entry(from, to)` exists and drag-to-move stays unbuilt. A note's *stem* is what gets edited; `with_md_extension` reappends `.md`, so a rename can never turn a note into a non-note. Every editor buffer at or under the old path has its `filePath` and title **rewritten in place** — dirty ones keep their unsaved edits — rather than being closed as deletion closes them: a rename destroys nothing, so it must cost nothing. For a note it also triggers a *wikilink rewrite*; for a directory it never does. |
| Vault entry duplication | `duplicate_entry` / `duplicate_entry_in` (`src-tauri/src/vault.rs`) | copy, clone, `fs::copy` | Copies a note *or* a directory beside itself under a derived name — `X copy`, then `X copy 2`, `X copy 3` on collision, always applied to the **stem** so `note.md` becomes `note copy.md`. Directories are copied by a hand-rolled recursive walk that skips symlinks, mirroring `build_tree`'s filter — no `fs_extra` dependency. Unlike *vault entry creation* it never opens the result in a buffer: duplicating is a filing action, so it only moves the sidebar cursor onto the copy. A derived name is never a link target that existed before, so it rewrites nothing. |
| Wikilink rewrite | `rewrite_wikilinks` (`src-tauri/src/vault.rs`) | link index, backlinks, reindex | The vault-wide scan repointing `[[old stem]]` at a renamed note's new stem. A **scan, never an index** (ADR 0016). Its grammar is narrower than the *wikilink* decoration's: the target is everything before the first `\|`, an anchor is preserved verbatim, and comparison is case-insensitive because the macOS filesystem is. It walks the file set the sidebar shows, minus the root `AGENTS.md`/`CLAUDE.md`, whose template holds a literal `[[Wikilinks]]`. **An ambiguous stem cancels it**: no rewrite plus a toast, the link model being unable to say which note was meant. Only a note rename triggers it. |
| Rename confirmation | `RenameEntryDialog` | rename dialog, rename prompt | The gate in front of a *wikilink rewrite*, shaped like the *delete confirmation* but shown **only when the scan finds at least one link**: a note nobody links to, and every directory, renames with no overlay at all. It exists to consent to writing in *other people's notes*, not to protect the renamed file, which is why `N = 0` means no dialog. Counts first, then the affected notes listed as in the dirty-buffer block. Its confirming action is a `secondary` button, never `primary` or `danger`: a rename is neither an AI action nor a destructive one (invariants 21, 27). |
| Sidebar context menu | `useContextMenuStore` / `SidebarContextMenu` (`src/stores/context-menu-store.ts`, `src/components/vault/SidebarContextMenu.tsx`) | popover, dropdown, native menu | App-drawn overlay, not `tauri::menu::Menu::popup` (ADR 0013). Mounted in `Layout`, **never** inside `Sidebar`, whose `overflow-y-auto` body would clip a menu rendered in place. Carries an explicit `target: string \| null` (`null` = vault root) rather than reading `cursorPath`. Expanded sidebar only, and mouse-only: every item already has a chord. Its item list is fixed, in four hairline-divided groups, each row carrying a glyph and a *live chord hint*. Only *presence* varies: an item that cannot apply to the target is **hidden, never disabled**. The two AI rows are disabled placeholders. |
| Delete confirmation | `requestDeleteConfirmation` / `useDeletePrompt` (`src/lib/vault/confirm-delete.ts`), `DeleteEntryDialog` | delete dialog, "are you sure" | The promise-shaped gate every deletion passes through, mirroring `useVaultSwitchPrompt` so `deleteVaultEntry` reads linearly. Always shown, even though trash makes the file recoverable, because the *unsaved edits* it discards are not, and this is the only surface that can disclose them. Its presentation is fixed: a *modal shell* at 460px carrying a `--danger-soft` icon tile, the target as a *vault display path* in its own mono field, counts-first copy with a concordant verb, the buffers line only when buffers will close, the dirty-buffer block last, and the app's only `danger` button. |
| Delete summary | the frontend-computed `{ counts, openBuffers, dirtyBuffers }` behind a *delete confirmation* | — | What the dialog body adapts to: entry counts for the deleted subtree, every buffer that will close, and the affected dirty buffers. Computed frontend-side by walking the cached `useSidebarStore.tree` and intersecting `editor.buffers` by path prefix — the vault tree is already in memory, so this needs no new IPC and `delete_entry` stays a bare `Result<()>`. |
| Vault agent context | `AGENT_CONTEXT_FILES` (`src-tauri/src/vault.rs`) | system prompt, vault README | The `AGENTS.md` and `CLAUDE.md` instructions scaffolded in an adopted vault root for engines running there. |
| Wikilink scan and rewrite | `WikilinkScan` / `WikilinkRewrite`, `scan_wikilink_targets` / `rewrite_wikilinks` (`src-tauri/src/{wikilink,vault}.rs`) | backlink index, global replace | The backend-only workflow that parses narrow `[[target]]` syntax across visible vault Markdown notes, reports target-stem ambiguity, and rewrites only unambiguous target spans while preserving aliases and anchors. Root agent-context templates are excluded; nested `AGENTS.md` remains a note. |
| Sidebar store | `useSidebarStore` (`src/stores/sidebar-store.ts`) | tree store, vault store | Owns cached tree, expanded directories, keyboard cursor, and pending entry draft or rename. |

| Markdown walker | `renderMarkdown` (`src/lib/editor/markdown-walker.tsx`) | markdown renderer, "the parser", preview renderer | `renderMarkdown` (`src/lib/editor/markdown-walker.tsx`), the `@lezer/markdown` tree to React element renderer behind the *read view* (ADR 0039). It emits React elements, never an HTML string, so raw HTML is **escaped text** and no sanitizer exists anywhere. ADR 0039 carries the mechanics. |
| Note header block | the breadcrumb / title / meta stack atop a *read view* | frontmatter, note metadata, "the header" | Three lines. The **breadcrumb** is the vault-relative directory plus the full basename, and **inert**. The **title** is the filename *stem*, a leading `# H1` being stripped from the source by `stripLeadingH1` before the parse so the note is not named twice. The **meta line** reads `edited <relative>`, `N links`, `N min read`, the first exactly that and never `<relative> ago`, `relativeTime`'s coarsest bucket being `now`. A `null` mtime **omits** the edited segment rather than placeholdering it, as a *note row* does; the breadcrumb degrades to the basename. No tags row: no tag concept exists. |
| Wikilink resolution | `resolveWikilink` (`src/lib/vault/resolve-wikilink.ts`) | link index, backlinks; *wikilink rewrite* | Maps a `[[target]]` stem to a vault path against the **cached sidebar tree**, the single resolver both the *read view* and the editor's *wikilink* decoration read, so a link cannot look different in the two views. A **scan of what is already in memory, never an index** (ADR 0016), and distinct from the *wikilink rewrite*, a backend walk for renames. Three outcomes, the third load-bearing: resolved, missing, or **ambiguous**, marked rather than guessed (invariant 38). `parseWikilinkDisplay` gives what the reader sees, the alias when present else the target. An **empty** target is *missing*. |
| Task toggle | `toggleTaskAt` (`src/lib/editor/toggle-task.ts`), `MarkdownRenderOptions.onToggleTask` | "the checkbox", inline editing, read-view editing | The *read view*'s **one** write (invariant 37). Ticking a box flips that marker's source range through `updateBufferContent`, so the note goes dirty and commits through the existing `EditorSaveRequest` lifecycle on `:w`. The offsets come **from the parse, never a text search**, so identically-worded rows stay distinct. `toggleTaskAt` returns the content **unchanged** for anything that is not `[ ]`, `[x]` or `[X]`, making a stale offset a no-op, and `ReadView` then declines to write at all. It reads `buffer.content` from the store at call time, so two quick clicks cannot share one snapshot. |

## Flagged ambiguities

- **Global versus editor Vim mode.** `GlobalMode` is the app-shell normal/command state; `EditorVimMode` is CodeMirror state for an editor buffer. Do not merge them. Only `EditorVimMode` is ever *rendered* — as bare text in the editor status cluster, never as a chip. They were once two identical `<Badge tone="muted">` 36px apart, which is precisely how users came to believe they were one thing (ADR 0009); the survivor has since dropped its box as well, so nothing in the app renders a mode badge at all.
- **Agent panel versus agent process.** `AgentPanel`, `agentOpen` and `FocusRegion 'agent'` name the invocable AI **region**; `AgentBackend`, `AgentEvent`, `AgentSource`, `AgentModel` and `agent_spawn`/`agent_send`/`agent_stop` name the **CLI subprocess** behind it. One word, two things, deliberately: the alternative was counter-renaming the CLI layer to `Engine*`, and "engine" was retired as an alias precisely because the model determines the source. The **transcript** vocabulary is a third thing again and stays `chat` — see *Agent panel*.
- **Adapter versus backend.** An adapter is a concrete per-engine translator; `AgentBackend` is the interface it implements.
- **Collapsed sidebar versus folded directory.** Two senses of "expanded" that are not the same state. `sidebarExpanded === false` collapses the whole region to the *sidebar rail*; a folded directory is one path missing from `useSidebarStore.expanded`. The rail can show a directory whose contents are folded, and expanding the sidebar does not unfold anything by itself.
- **Entry draft versus entry rename.** Both render an inline input on a sidebar row and share one input component, but they are different states in different slots: an `EntryDraft` is an entry that does not exist yet, `renamePath` points at one that does. Only the second can break links or invalidate an open buffer's path. A third `EntryDraftKind` was rejected for exactly that reason.
- **Entry draft versus dirty editor buffer.** An `EntryDraft` has not reached disk. A dirty buffer is an existing note with unsaved content.
- **Buffer versus tab.** `EditorBuffer` is session state; an editor tab is its UI representation.
- **Engine versus model.** The model is user-selected; its derived `AgentSource` identifies the CLI. Persist the model, never a separate engine.
- **Three chat stores.** `useChatStore` owns the in-memory transcript, `chats.rs`/`chatsService` own durable storage, and `useChatHistoryStore` owns history-browser view state.
